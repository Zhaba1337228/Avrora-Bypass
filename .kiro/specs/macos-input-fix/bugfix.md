# macOS: запуск и системный ввод

## Текущее поведение
Пользователь сообщает, что приложение на macOS не работает; симптом и версия macOS неизвестны. Подтверждено чтением кода: режим компенсации отступа посылает Shift+Home, не проверяя платформу; проверка macOS всегда сообщает, что системный ввод доступен, не проверяя разрешения. Причина сообщения пользователя пока не установлена.

## Ожидаемое поведение
Приложение на macOS запускается и позволяет управлять посимвольным вводом, включая компенсацию отступов. При отсутствии необходимых разрешений или зависимостей пользователь получает понятное сообщение с действиями. На macOS применяется подходящее сочетание для выделения до начала строки; взаимодействие конкретного редактора проверяется отдельно.

## Не меняется
Работа Windows и Linux, формат исходного текста, F8/F9 и назначение остальных функций. Проверка не подразумевает запуск под root.

## Проверка
Автотесты моделируют системные ответы и клавиатурные действия; существующие тесты проходят. Проверка на macOS выполнена пользователем: 2026-10-27 он сообщил, что всё работает. Детали проверки отдельных функций не приводились.

## Уточнение симптома
Приложение открывается, но после нажатия кнопки «Старт» вылетает. Момент (сразу или после отсчёта), текст ошибки и способ запуска неизвестны. Код запускает фоновый поток; Python-исключения внутри него выводятся как событие ошибки, но это не исключает нативного аварийного завершения. Причина пока не подтверждена.

## Дополнительные критерии
Проверить путь от нажатия «Старт» до создания системного backend и первого символа; Python-ошибки должны отображаться без закрытия окна. При нативном аварийном завершении необходим macOS crash report или вывод терминала для установления причины. Не объявлять исправление проверенным без воспроизведения на Mac.

## Исследование возможной причины
В открытом upstream issue pynput #366 описан SIGILL на macOS M1 при отправке клавиши из фонового потока в приложении Tkinter. В этом проекте TypingWorker также создаёт Controller и отправляет клавиши в фоновом потоке после отсчёта. Это сильная гипотеза, а не доказанный root cause для конкретного Mac. Источник: https://github.com/moses-palmer/pynput/issues/366
Также Listener pynput выполняет callbacks в отдельном потоке, а код вызывает Tk after из callback; это отдельная область для проверки и не доказывает причину вылета по кнопке. Источник: https://github.com/moses-palmer/pynput/blob/master/docs/keyboard-usage.rst

## Новые данные
Скриншот пользователя сообщает EXC_BREAKPOINT (SIGTRAP), Thread 11, TSMGetInputSourceProperty → _dispatch_assert_queue_fail; Python 3.13.9, Tkinter и разрешения работают. Полный стек и привязка потока к компоненту не предоставлены. Дополнительный опубликованный случай связывает аналогичный стек с фоновым pynput listener: https://github.com/isair/jarvis/issues/172. Необходимо устранить обращения к обработке раскладки из фонового потока как при вводе, так и при прослушивании.

## Статус
Изменения реализованы и проверены 16 тестами на Windows с имитацией macOS API. 2026-10-27 пользователь сообщил, что на Mac всё работает. Отдельные проверенные сценарии не перечислены; причина исходного падения не доказана полным стеком.
